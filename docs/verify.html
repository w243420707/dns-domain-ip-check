DNS 池守护 · 验收清单

按顺序做完 7 步，约 15 分钟。每步都写了"怎么算通过"和"不对时看哪里"。

下载 APK 仓库 Release

它在你手机里干的事

域名列表→ 解析 A 记录→ 多端口全通→ 取最快 N 条→ 写入 Cloudflare→ 坏一条只修一条
01

装上去

在云手机的浏览器里直接打开 Release 里的 APK 下载安装，或用电脑 adb 推过去。

adb install -r dns-pool-1.0.0.apk
通过桌面出现「DNS 池守护」，打开后是三页签：状态 / 槽位 / 设置。
装不上：确认 Android 8.0 以上；部分云手机默认禁止"未知来源"，需要在系统设置里放行当前浏览器或文件管理器。
02

把后台放行

这一步决定它能不能 7×24 活着，比什么都重要。

  • 状态页顶部提示条 → 允许通知（Android 13+ 必须）
  • 同一提示条 → 加入电池优化白名单
  • 云手机厂商自己的"自启动 / 后台运行白名单"里再放行一次（每家叫法不同）
通过通知栏出现常驻通知「DNS 池守护 · 运行中」，划掉最近任务后通知仍在。
划掉就消失：说明厂商在杀进程，回到上一步找厂商的白名单设置；App 内部已用 specialUse 前台服务 + 15 分钟看门狗。
03

接上 Cloudflare

Cloudflare 控制台 → 我的个人资料 → API 令牌 → 创建自定义令牌。权限只给两项：

  • Zone → DNS → 编辑
  • Zone → Zone → 读取
  • Zone 资源限定到你要用的那个域名

回到 App 设置页：粘贴 Token、填根域名（例如 example.com，不要带 https://），点旁边的「校验」。

通过提示「Token 有效；Zone example.com 已用 x/200 条」，配额数字和你在 CF 后台看到的一致。
Token 无效：多半是复制时带了空格或被撤销，重新生成一个。权限不足：令牌少了 Zone:Read 或 DNS:Edit。
04

先自检，再动手

填好端口（默认 443,80，全部端口都通才算可用）和域名列表（一行一个，# 开头是注释），然后点「自检」。

通过9 项全绿，最后一行是「—— 9/9 通过 ——」。其中「差异预览」会告诉你本次将要创建多少条。
DNS 解析失败：目标域名的系统 DNS 被污染，去 DNS 分组把解析方式切成"指定 UDP"，填 223.5.5.5 再测。端口不通：换一个域名或端口试，确认不是本机网络问题。
05

第一次发布

长按「重建」= 预览差异，看过数字后再点「重建」（会二次确认）。默认 N=200，槽位模式下记录名是 n001.你的域名 一直排到 n200。

写完后去 Cloudflare 后台开 DNS 记录页，鼠标悬停任意一条记录的备注图标：

dslk1|s=001|r=42/58|u=1763100000|d=jp1.example.net
通过记录数与 N 一致；备注以 dslk1| 开头且槽位号连续；颜色是灰云（DNS only）。
提示额度不足：免费版 Zone 上限 200 条（2024-09 后创建），把 N 调小到提示的数字以内。提示"记录名不符"：说明之前用过别的前缀，先到设置页「删除我管理的记录」再重建。
06

验收核心：改坏一条，看它会不会只修这一条

这是整个 App 的关键行为，务必实测一次。

  • 在 Cloudflare 后台把 n001 的 IP 手工改成 1.1.1.1
  • 回 App 状态页点「跑一轮」，等它判定失败（默认连续 2 次才动手，所以跑两轮）
  • 再刷新 Cloudflare 后台
通过n001 被换成一个可用 IP、备注里的时间戳更新；其余 199 条记录的时间戳完全没变；日志里出现「槽位 1 …→…（xx ms）」。
全部被重写：不正常，说明差异计划器失效，请保留 CF 审计日志反馈。一直不修：检查候选池数字是否为 0，为 0 就把域名列表加长或点「重建」重新补货。
07

断网恢复与日常巡检

开飞行模式 5 分钟再关掉。

通过通知恢复为「运行中」，状态页"最近写入"重新变成刚刚；日志里有一条「网络恢复，检查循环」。
日常只看三个数正常 x/200 · 候选池 n · 最后心跳
心跳变红超过 120 秒没更新 = 服务被杀了
候选池见底等于 0 就该补域名或重建
想彻底重来：设置页最下方「删除我管理的记录」，只删备注以 dslk1 开头的记录，别人的记录一条都不动。
想换手机：装好后填同一个 Token 和根域名即可——程序会扫描备注把 200 个槽位的记录 ID 认领回来，不会重复建。
